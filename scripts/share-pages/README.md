# Share-page generator backup

The court-actor share pages under `public/court-actors/<state>/<slug>/share.html`
are generated by scripts that live in a sibling working directory:

    /Users/meghannmiller/Code/court-actor-posts/_scripts/

That directory is not a git repo. To make sure script changes survive a
machine wipe or a regen on a different host, the share-page generator
sources are mirrored here whenever they change.

## What's in this folder

- `render_spotlight.py` — backup copy of the per-actor share/spotlight
  HTML generator. Authoritative source lives at:
  `/Users/meghannmiller/Code/court-actor-posts/_scripts/render_spotlight.py`.
  Diff and re-sync if the working copy drifts.

## Sync from working copy → versioned backup

    cp /Users/meghannmiller/Code/court-actor-posts/_scripts/render_spotlight.py \
       scripts/share-pages/render_spotlight.py

## Restore versioned backup → working copy (after machine wipe / new clone)

    mkdir -p /Users/meghannmiller/Code/court-actor-posts/_scripts
    cp scripts/share-pages/render_spotlight.py \
       /Users/meghannmiller/Code/court-actor-posts/_scripts/render_spotlight.py

## Regen pipeline (chained)

The end-to-end regen reads from the working copy:

    cd /Users/meghannmiller/Code/court-actor-posts
    python3 _scripts/regen_all_deployed_actors.py

That script runs spotlight_build → render_spotlight → deploy_actor_to_site for
every actor currently in `public/court-actors/manifest.json`. It writes the
refreshed share.html, spec.json, frame PNGs, and image_1080.png back into this
repo's `public/court-actors/<state>/<slug>/`.

## Notable features the backup captures

- Statewide Registry family count badge on Frame 1 (cover). Pulled from
  `spec.state_stats.state_family_count` and rendered as a small caption
  beneath the actor-specific count (e.g. "321 CA families in the Registry").
  Hidden when the state count is missing/zero so the share page never
  shows "0" or "Review" publicly.
