# Share-page generator backup

The court-actor share pages under `public/court-actors/<state>/<slug>/share.html`
are generated by scripts that live in a sibling working directory:

    /Users/meghannmiller/Code/court-actor-posts/_scripts/

That directory is not a git repo. To make sure script changes survive a
machine wipe or a regen on a different host, the share-page generator
sources are mirrored here whenever they change.

## What's in this folder

- `render_spotlight.py` — backup of the per-actor share/spotlight HTML
  generator. Source: `_scripts/render_spotlight.py`.
- `spotlight_build.py` — backup of the spec builder that pulls live counts
  from `/api/survey/court-actors` and headline state stats from
  `scripts/pdf/state_stats_for_share.py` so the share slide and the
  public PDF can never drift. Source: `_scripts/spotlight_build.py`.
- `verify_share_consistency.py` — pre-push regression gate. Walks the
  deployed manifest and asserts API ↔ spec.json ↔ share.html agreement
  for counts and Frame 5 state stats. Includes Dianna Russell + Anthony
  Miller as explicit fixtures. Source: `_scripts/verify_share_consistency.py`.

## Sync from working copy → versioned backup

    for f in render_spotlight.py spotlight_build.py verify_share_consistency.py; do
      cp "/Users/meghannmiller/Code/court-actor-posts/_scripts/$f" \
         "scripts/share-pages/$f"
    done

## Restore versioned backup → working copy (after machine wipe / new clone)

    mkdir -p /Users/meghannmiller/Code/court-actor-posts/_scripts
    for f in render_spotlight.py spotlight_build.py verify_share_consistency.py; do
      cp "scripts/share-pages/$f" \
         "/Users/meghannmiller/Code/court-actor-posts/_scripts/$f"
    done

## Regen pipeline (chained)

The end-to-end regen reads from the working copy:

    cd /Users/meghannmiller/Code/court-actor-posts
    python3 _scripts/regen_all_deployed_actors.py

That script runs spotlight_build → render_spotlight → deploy_actor_to_site for
every actor currently in `public/court-actors/manifest.json`. It writes the
refreshed share.html, spec.json, frame PNGs, and image_1080.png back into this
repo's `public/court-actors/<state>/<slug>/`.

## Notable features the backup captures

- Statewide Registry family count badge on Frame 1 (cover). Pulled from
  `spec.state_stats.state_family_count` and rendered as a small caption
  beneath the actor-specific count (e.g. "321 CA families in the Registry").
  Hidden when the state count is missing/zero so the share page never
  shows "0" or "Review" publicly.
- Multi-page parent quote slides. `render_spotlight.story_quotes(spec, n=None)`
  reads every publishable actor-specific `public_comment`, removes unsafe or
  duplicate fragments, and `chunk_quote_pages` creates additional `WHAT
  FAMILIES SAY` slides when the safe quote list is longer than one page.
  `verify_share_consistency.py --asset-only` compares the exact normalized
  quote list the renderer would choose against the checked-in `share.html`, so
  stale generated HTML cannot silently drop a newly selected parent quote or
  keep an old quote after selector logic changes. The intentional no-quote
  placeholder ("Families are adding their reports to the public record.") is
  allowed only when the renderer finds no safe quote source.
- Best-line extraction. The selector scores candidate sentences/clauses and
  surfaces the strongest, not just the opening line. A contentless lead (e.g.
  "this judge came in New.") is demoted, and `_event_clause_candidates` rescues
  a strong conduct event buried inside a run-on sentence ("…and literally
  dismantled a six-figure judgment and…" → "Literally dismantled a six-figure
  judgment"). Conduct verbs paired with a court outcome (`ACTION_VERBS` ×
  `RULING_NOUNS`) score highest. Complement verbs ("allowed X **to** …") keep
  their `to …` complement so they never fragment into "Allowed opposing
  counsel". Because `render_spotlight.py` is in `regenerate_deployed_actors.py`'s
  `TEMPLATE_INPUT_FILES`, any change here invalidates every actor's
  `input_hash`, so the next regeneration re-renders all share pages with the
  improved selection. Covered by `test_quote_selection.py`.
- Per-actor quote curation. If a merged family note contains multiple usable
  conduct clauses plus unsafe/noisy language, use
  `actor_overrides.json.replace_public_comments` instead of hand-editing
  `share.html` or `spec.json`. The replacement list is written into the public
  spec and flows through both slides and PDFs on future regenerations. Keep
  stand-alone name-calling out of slides; `render_spotlight._is_insult_only`
  rejects short insult-only fragments globally, and actor overrides can also
  exclude specific substrings when one actor needs a stricter cut.
- Live-post guardrail. Before publishing a newly deployed actor, run
  `verify_share_consistency.py` without `--asset-only` when credentials are
  available. A share page is not healthy if `spec.json["unresolved"]` contains
  `court_actors: no rows match` and there are no quote sources; repair the
  manifest/bucket/name and force regeneration before posting.
- Admin deploys should persist the resolved public bucket display name, not a
  manually typed label. The GitHub regeneration command uses the manifest
  `display_name` to resolve Supabase rows, so a typo here can produce a
  Jennifer-style blank actor share even when the photo committed.
- Photo live-post guardrail. `manifest.photo_url` only proves the public card
  can show an image. The social share template is ready only when generated
  `spec.json` has `photo.exists=true` and `share.html` no longer contains
  `{{ACTOR.IMAGE_URL}}`. The regeneration cache must not skip actors in that
  half-wired state.
- Public report fallback guardrail. The live actor panel should not disappear
  just because Supabase is slow. `/api/survey/court-actors` must return the
  generated actor snapshot (`loadStaticPublicActors()`) on read timeouts or
  other transient failures instead of an empty actor array.
- Admin actor repair/regeneration guardrail. Actor slide and portrait repair
  actions must dispatch `regenerate-court-actor-shares.yml` with `force: "true"`
  so the actor share-page cache cannot skip the repair. State PDF regeneration
  remains independent in `regenerate-state-pdfs.yml` and publishes as soon as
  its PDF release gates pass.
- Targeted actor regeneration. `regenerate_deployed_actors.py` accepts repeated
  `--actor <slug>` filters, which is useful for repairing a small set of live
  share pages without regenerating an entire state. Use `--force` for quote,
  photo, PDF, or slide repairs so `.regen-cache.json` cannot reuse stale output.
- Duplicate-card guardrail. `verify_share_consistency.py`
  `check_duplicate_manifest_entries` fails the gate when two manifest entries
  describe the same person — either a shared `actor_bucket_key` or a shared
  state + honorific/spelling-normalized name (`Dr. Gage Stermensky` ≡
  `Gage Stermensky`). This catches the re-deploy-under-a-new-slug bug that
  left orphan cards live. The deploy route's `addActorToManifest`
  (`lib/court-actor-deploy.ts`) now replaces a prior entry that shares the new
  bucket key so the duplicate is never written in the first place. Unit
  coverage: `test_duplicate_detection.py`. To resolve an existing pair, keep
  the entry whose count resolves against the live API and delete the orphan
  folder + manifest entry.
